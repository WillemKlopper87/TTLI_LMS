The last of the four gaps this item named: the access token lived only in a module variable, so every reload dropped the session; there was no logout at all; and the magic-link and password-reset URLs that `routers/auth.py` and `routers/guest_access.py` have been emailing since Phase 1 pointed at pages that did not exist, so every one of those links 404'd on arrival.

Always 204 whether or not the token was live, so logout is idempotent and never leaks token state through its status code. Audit-logged as `AuditAction.LOGOUT` (the enum value already existed, unused).

## 9c. Multi-tier subscriptions + free-preview lessons

Requested directly (not part of the 5-item backlog above): a user question — "if someone buys a course then upgrades to a subscription, is that workflow built, and what stops abusive tier-hopping?" — surfaced that neither subscriptions nor a free-preview concept existed at all. Investigated, planned, and built both. Resolves [01 §1.4](01_PRD.md#14-open-decisions-blocking-phase-0-sign-off) #5 (REQ-PAY-12).

- [x] **Multi-tier subscriptions.** New `subscription_plans`/`subscription_plan_courses`/`subscriptions` tables (migration `0021`, plus a second demo course seeded so the two demo plans — "Leadership Track"/"Full Library" — bundle meaningfully different course sets). Renewals are funded through the *existing* EFT/PO manual-approval checkout, not automatic card charging — no Payfast/Netcash integration exists (`routers/orders.py`'s own docstring, unchanged). Each billing period is a real `Order` (`Order.subscription_id`); fulfilling it grants a fresh `Entitlement` per bundled course via `entitlements.expires_at` — a column that existed since `0009` but was dead until now.
- [x] **The anti-abuse mechanics the original question asked about, concretely, not just in prose:** upgrading is immediate, always a new full-price order for a full new period (the old period's remainder is forfeited, no proration — this codebase has no credit-note mechanism to prorate against).
