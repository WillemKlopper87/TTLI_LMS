# TTLI — Codebase Critique (fable5.1_review)

**Date:** 2026-09-03
**Tree reviewed:** `main` at `10e759f` **plus the uncommitted working tree** (42 modified files; `0041_lesson_blocks.py`, `services/lesson_blocks.py`, `services/workshops/`, and four new test files untracked). Several of the most serious findings are consequences of that half-landed remediation and will bite on the next commit.
**Method:** six independent, read-only reviewers each read their area in full — (1) API core/routers/auth (`main.py`, all of `core/`, all 34 routers), (2) commerce/money/integration services + workers, (3) learning-domain services + all 29 models + all 30 schemas + all 41 migrations, (4) web admin/BFF/auth plumbing (`proxy.ts`, all of `lib/`, all BFF routes, all 47 admin files), (5) web public/learn/checkout/components/e2e, (6) tests/CI/containers/config/docs — then merged, de-duplicated and re-ranked here. Every finding cites `file:line` from the current tree. Nothing was edited or run.

This is a *fresh* read, not a restatement of `TTLI_Audit_Report_2026-09-02.md`. That audit contained **no money-correctness, no learning-integrity, and no tenant-authoring findings**; everything in §1–§2 under those headings is new. Prior items still open are in §6.

## 0. Executive summary

The platform's foundations are unusually strong for its size: forced RLS on every tenant table with a host-and-JWT double assertion, refresh-token rotation with family revocation, reservation-first idempotency, a correct Payfast webhook order of operations, textbook OIDC, real-service tests on Postgres 18 as the RLS-bound user, SHA-pinned actions and keyless cosign. The problems this review found sit in four places the audit never looked:

1. **The uncommitted 0041 lesson-block remediation is internally inconsistent.** The API changed the lesson contract; the learner player, preview page, admin wizard detach button, generated client, `test_preview.py`, `test_course_wizard.py`, the e2e fixtures and the docs migration-range gate were not updated. On the next commit: every lesson in the player renders empty, video heartbeats 422, at least three CI gates go red, and the authenticated browser job cannot pass — while the `images` job still builds, signs and pushes the image because it has no `needs:`.
2. **Learning integrity can be gamed in two requests.** Prerequisite locking exists only for display; a learner can start and complete the *last* lesson and receive a certificate, PDF, badge, and a downstream learning-path certificate.
3. **Money is wrong in three ways.** VAT-inclusive prices are charged 15% too much (and the new unit test enshrines the wrong number); concurrent approvals double-fulfil an order (two invoices, two ledger entries, double revenue); concurrent refunds double-refund; a buyer who pays twice has the second Payfast charge silently lost.
4. **Tenant boundaries have three holes the RLS design can't see.** The content-authoring surface is global and the tenant `admin` role carries `course:edit`, so any customer admin can read/edit every other tenant's bespoke courses and quiz answer keys; suspending a user does not end their sessions; the org progress report leaks every learner's decrypted full name to any seat-holder.

Counts after merging: **3 critical, 20 high, ~45 medium, ~60 low.**

## 1. CRITICAL

### C-1. The 0041 lesson-block remediation breaks the learner, the admin, four CI gates and the browser job
Migration `apps/api/alembic/versions/0041_lesson_blocks.py` and the modified routers moved content attachment to per-block routes (`routers/assessment.py:309,544,852`, `routers/media.py:295,452`, `routers/course_wizard.py:215-264`; the old `DELETE /lessons/{id}/activity` is gone per `course_wizard.py:209`) and replaced the lesson progress shape with `blocks: list[...]` (`schemas/learning.py:31-55`; `git diff` shows `-activity_type`, `-video_asset_id`, `-quiz_id`). Not migrated with it:

- **Learner player renders nothing.** `apps/web/app/learn/[enrolmentId]/types.ts:16-33` still types `activity_type`/`video_asset_id`/`quiz_id`/`survey_id`/`assignment_id`/`body`; `page.tsx:183-223` renders solely off those. Every lesson becomes a title, the requirements panel and a bare "Mark complete". Same for `/preview/{id}` (`preview/[lessonId]/page.tsx:12-21, 207-221` vs `schemas/courses.py:303-306`).

- **Admin wizard 404s.** `apps/web/app/admin/courses/steps/step-content.tsx:105` still `DELETE`s `/lessons/{id}/activity`.
- **`api-client drift` gate fails.** `packages/api-client/src/schema.gen.ts` still contains `/lessons/{lesson_id}/video|activity` and has zero `lessons/{lesson_id}/blocks`; `ci.yml:213-218` regenerates and `git diff --exit-code`s it.
- **Tracked tests call removed routes.** `tests/test_preview.py:266-269, 304-307, 337-340, 423-440` (`/lessons/{id}/quiz|survey|assignment|video`, asserting 204); `tests/test_course_wizard.py:398` asserts the removed detach route returns 403 (it now 404s).
- **Docs gate trips on itself.** `docs/check_links.py:36-37,78-89` (modified in this tree) newly fails the build if `NEXT_AGENT_BRIEF.md`'s migration range doesn't match the highest version file; `NEXT_AGENT_BRIEF.md:42` says `0001–0040`; `0041` exists.
- **Browser job cannot pass.** `apps/web/e2e/fixtures/author-content.ts:96` sends `body` on `LessonCreateRequest` (field removed — pydantic silently drops it); `:138,170,196` POST to `/lessons/{id}/quiz|survey|assignment`. Because `types.ts` is hand-written and nothing under `app/learn` imports `@ttli/api-client` (only `admin/question-bank` does), the OpenAPI drift gate could never have caught the web side — precisely the prior audit's M7 warning, now materialised. `docs/STATUS.md:71` "all 38 Playwright specs pass" is stale.

### C-2. Lesson prerequisite locking exists only on read — complete the last lesson first, get a certificate
- `services/enrolment.py:767-791` (`start_lesson`) creates a `LessonCompletion` for **any** lesson; no check that prior lessons are completed. `:838-849` (`complete_lesson`) requires only that a completion row exists and merged rules pass. `:893-917`: when `_next_lesson()` returns `None` (the lesson is last by position) it sets `enrolment.completed_at` and calls `issue_for_completed_enrolment` — never checking that other lessons are done. The docstring at `:833-837` explicitly assumes "strict-linear locking", but that locking is only *computed* in `get_progress` (`:999-1012`) for display. `routers/learning.py:254-260` adds no gate. The only test (`tests/test_learning.py:284-291`) asserts the displayed `locked` flag, not that `POST /lessons/{last}/start` is refused.
- Failure: `POST /lessons/{last_lesson_id}/start`, wait out `minimum_time_seconds` (often absent), `/complete` → course complete, certificate + PDF + badge, and via `find_path_enrolments_for_course_completion` (`:929-963`) a learning-path certificate, because `all_member_courses_completed` (`learning_paths.py:758-770`) only counts `Enrolment.completed_at`. Defeats REQ-BYPASS-01/10 and REQ-CRED-01.

### C-3. Image publish/sign is not gated on any test job; deploy scripts deploy `HEAD` regardless
`ci.yml:324-333`: the `images` job has **no `needs:`** — `quality`, `secrets`, `web`, `images`, `authenticated-e2e` are five independent jobs. On a push to `main`, `images` builds, Trivy-scans, pushes `ghcr.io/…/ttli-api:sha-$GIT_SHA` and cosign-signs it (`:364-411`) even when pytest/mypy/drift failed or gitleaks found a key. The cosign identity attests "built by ci.yml on main", not "passed CI". `scripts/rolling-update.sh:39-42,69` does `git pull --ff-only` and deploys `$(git rev-parse HEAD)` with no run-status check; `deploy-single-vm.sh:282` likewise. With the direct-to-main convention (`BACKLOG.md:132` "no PRs"), C-1's red commit is one `rolling-update.sh` away from production. Signature verification on the host is also optional: both scripts `warn` and continue if cosign is absent (`rolling-update.sh:88-97`, `deploy-single-vm.sh:288-296`), and neither installs it.

## 2. HIGH

### Money (commerce services)

**H-1. VAT-inclusive prices are charged 15% too much; the extracted pricing test asserts the wrong number.** `services/orders.py:99-111`: `line_tax = subtotal * rate` (correct only for exclusive; inclusive is `subtotal * rate / (1+rate)`) and `grand_total = subtotal + tax_total` unconditionally, while `line_total` for inclusive is `subtotal` (`:102`). One inclusive R115 line → `tax_amount=17.25` (should be 15.00), `grand_total=132.25` (should be 115.00). `Payment.amount` (`:240,288,338`) and the invoice (`invoicing.py:76-78`) copy `grand_total`, so the buyer is charged 15% extra and the tax invoice states R17.25 VAT on a R115 sale. `tests/test_orders_pricing.py:36-53` enshrines `tax == 17.25` and never asserts `grand_total` for the inclusive case. Admins can set `inclusive` via `routers/catalogue.py:192`, `routers/subscriptions.py:117`; `docs/05_COMMERCIAL.md:34,224` anticipates it.

**H-2. Double fulfilment of the same order under concurrent approvals.** `routers/orders.py:389-392` loads `Payment`/`Order` with plain `session.get`; `orders.py:650-651, 672-673` check status in Python; no `FOR UPDATE`. Two finance users (or one with two `Idempotency-Key`s — scope is `(tenant,user,key,path)`, `alembic/0023:185-190`) both pass and both call `_fulfil_order`: two invoices (`invoices` has no unique on `order_id`, `models/commerce.py:343-360`), two `INVOICE_ISSUED` + `PAYMENT_RECEIVED` ledger rows (`orders.py:578-600`), duplicated entitlements, revenue double-counted. **H-3. Same race double-refunds:** `refunds.py:93, 117-118` unlocked checks; no unique on `credit_notes.invoice_id`/`refunds.order_id` (`models/commerce.py:391-397, 437`) — and both tables are append-only, so it can't be cleaned up in-app. Contrast `workshops/booking.py:307-340`, which locks correctly.

**H-4. A buyer who pays twice has the second Payfast charge silently lost.** `orders.py:309-315` creates a fresh `Payment` per checkout (two tabs → two charges). The second ITN passes signature/source/amount, then `fulfil_card_payment` raises (`:700-701`) → the exception propagates out of `tenant_session` (`core/db.py:87`) → the `PaymentWebhook` row (`webhooks.py:154-162`) is **not** written, no audit row, Payfast retries until it gives up. `payment.status` stays `pending` forever; the docstring's "always return 200 once persisted" (`webhooks.py:19-20`) isn't what happens.

**H-5. arq's default 300s `job_timeout` will cancel real transcodes and orphan ffmpeg.** `workers/main.py:292-308` sets `max_tries=1` but no `job_timeout`. `CancelledError` isn't caught by `pipeline.py:116-121`; `asset.state` stays `transcoding` (committed at `:59`), `_failed_transcodes` (`operations.py:197-229`) never sees it, and the ffmpeg child from `transcoder.py:50-56` is never killed.

### Learning integrity

**H-6. Video watch time multiplied by concurrent heartbeats.** `services/video_progress.py:71-103`: row read without `FOR UPDATE`; N parallel requests each add up to 30s per 30s wall-clock. Nothing bounds `elapsed` by `(position delta)/playback_rate`, so time accrues while paused. (And per C-1, on this tree heartbeats don't work at all.)

**H-7. Attempt limits and version counters are check-then-insert with no uniqueness backstop.** `quiz.py:114-131` counts then inserts `attempt_number = n+1`; no unique `(enrolment_id, quiz_id, attempt_number)` (`models/assessment.py:80-82`) → parallel starts bypass `max_attempts`. `quiz.py:191-192` submit: no unique `(attempt_id, question_id)` → duplicate `QuizAnswer`s double-count points in `grade_text_answer` (`:289-296`). `assignment.py:65-68` version likewise.

**H-8. A quiz attempt is consumed every time the quiz component mounts.** `apps/web/app/learn/[enrolmentId]/quiz-player.tsx:68-85` POSTs `/quizzes/{id}/attempts` in a mount effect; there is no resume-open-attempt path (`assessment.py:332-346`). Clicking another lesson and back, a reload, `router.replace` in `select()` (`page.tsx:110`), or dev StrictMode each burn an attempt; with `max_attempts: 3` the learner sees "This quiz could not be started" before answering anything.

**H-9. Media/quiz/survey/assignment "public preview" access ignores course state and tenant assignment.** `enrolment.py:181-226` (`_has_access_to_media`) and `:273-311` return `True` as soon as *any* referencing block is in a `public` lesson — no `Course.state == "published"`, no `CourseTenantAssignment` predicate (contrast `courses.py:447-462`). A signed-in user of tenant B can mint playback URLs for a draft or tenant-A-only bespoke course. `.first()` at `:295` makes the winning lesson arbitrary.

**H-10. Re-booking a cancelled workshop session 500s.** `workshops/booking.py:377-423`: a cancelled `Booking` is reused (`:399-402`) then an `AttendanceRecord` is unconditionally inserted (`:415-423`); `_cancel_booking_row` (`:576-582`) never deletes the old record; `uq_attendance_records_booking_id` (`models/workshop.py:270`) fires. Cancel-then-rebook and reschedule-back are both broken.

### Tenancy, auth, PII

**H-11. The family's 30-day rolling window re-extends on every rotation (`tokens.py:80`), so suspension is cosmetic until voluntary logout. Password-reset correctly calls `revoke_all_for_user` (`auth.py:644`); suspension should too.

**H-13. Org progress report leaks every learner's decrypted full name to any org *member*.** `services/reports.py:243-252`: `display_name = full_name or masked_email` regardless of `individual_visible`; only the email is masked, contradicting the docstring (`:14-18`) and `schemas/reports.py:12-13`. `routers/organisations.py:175-177` gates on `require_membership`, which accepts relationship `member` — an ordinary seat-holder enumerates every colleague's name, status, progress and at-risk flag. Also N+1 (`:258`) and no `tenant_id` predicate (`:189-206`).

**H-14. Argon2 password verification runs synchronously on the event loop.** `services/identity.py:131,135,137` (and `:192,238`) call ~250ms Argon2id (`core/security.py:21-23`) directly from async handlers; no `to_thread` anywhere on the auth path. ~4 logins/s from different IPs (inside the 10/min/IP limit) pins the loop; every heartbeat, approval and webhook stalls.

## 3. MEDIUM

### API / auth / tenancy
- **M-1.** MFA can be silently re-enrolled by anyone holding a bearer (`routers/auth.py:507-575`; `identity.enroll_mfa` overwrites the secret) — no re-auth, no existing-factor check.
- **M-2.** Per-IP rate limiting trusts the *first* `X-Forwarded-For` hop (`core/net.py:28-34`) while the BFF forwards inbound XFF verbatim (`app/api/bff/[...path]/route.ts:38-39`, `lib/bff-auth.ts:23-24`); Next only fills XFF when absent. Behind an appending proxy (the documented Container Apps target) every IP-keyed limit — login, magic-link, guest-access creation, leads, verify — is bypassable. Both reviewers found this independently.
- **M-3.** No request-body size limit anywhere: BFF `arrayBuffer()`s everything (`route.ts:62`), Caddy sets no `max_size`, and every upload is `await file.read()` before checks (`orders.py:259,322`, `assessment.py:895`, `media.py:123,258,383`, `organisations.py:256`, `tenant_branding.py:131`); unauthenticated `webhooks.py:60-61` too. clamd's default `StreamMaxLength` is 25 MiB with no override in compose, so the 500 MB `bypass_max_size_bytes` path can never work — any video over ~25 MiB gets `ScanUnavailable` → 503.
- **M-4.** `POST /auth/sso/start` is anonymous, unlimited, runs uncached discovery and **synchronous** `socket.getaddrinfo` on the loop (`routers/sso.py:111-139`, `services/oidc.py:110-125, 192`); same blocking DNS on callback and `PUT /tenant/sso`.
- **M-5.** Unverified custom domains resolve to a tenant immediately (`core/tenancy.py:47-60` never checks `verified_at`; hostnames are globally unique) — tenant A can squat tenant B's future hostname.
- **M-6.** CSV formula injection: `routers/audit.py:139-156` (`user_agent`, `actor_email` — a `User-Agent: =HYPERLINK(...)` on a failed login lands in the admin's Excel), `invoices.py:150`, `analytics.py:2188`, `assessment.py:754`.

- **M-8.** Whole-file media serving with no per-token concurrency bound (`media.py:582-588, 666-689`; `playback.py:49` caps minting, not serving) — one learner with 20 parallel GETs pins 10 GB.
- **M-9.** Subscription orders bypass idempotency: `core/idempotency.py:98-102` scopes only `POST /orders`/approve/reject/refund; `subscriptions.py:198-302` (`subscribe`, `change_plan`, `renew`) create orders with no key.

## 7. Genuinely well done

- **Tenant double-assertion**: host-resolved tenant *and* JWT `tid` must agree (`core/deps.py:193-197`) on top of `SET LOCAL app.tenant_id` + `FORCE ROW LEVEL SECURITY` on every tenant table from 0001 with `NULLIF` fail-closed policies; cross-tenant maintenance via narrow `SECURITY DEFINER` functions; the BFF overwrites `X-Tenant-Host` from `Host` and all server reads are `no-store` — no Next data-cache path can serve tenant A's data to B.
- **Refresh-token design** (`services/tokens.py:95-186`): single consuming UPDATE guarded by `consumed_at IS NULL`, family revocation on reuse, fingerprint mismatch refused without revoking; cross-tab rotation serialised with Web Locks (`lib/session-context.tsx:65-102`); refresh token stripped from every JSON body and read only from a path-scoped HttpOnly cookie (`lib/bff-cookies.ts:16-30`, `bff-auth.ts:78-83`) — CSRF-safe by construction. Logout jti-denylist actually works.
- **Idempotency** reservation-before-handler with `ON CONFLICT DO NOTHING`, in-flight 409, stale takeover, never-cache-5xx (`core/idempotency.py:152-296`), reasoning written down.
- **OIDC** (`services/oidc.py`): server-derived redirect URI, PKCE S256, nonce bound to state, single-use state via `GETDEL` + `compare_digest`, browser-binding hash, issuer/audience/`require` claims, discovery-issuer equality, HTTPS-only, real SSRF guard on every fetch with the DNS-rebinding residual honestly documented.
- **Payfast webhook** order of operations: SECURITY DEFINER tenant resolution → order-preserving signature → live source confirmation → `provider_event_id` unique-index replay guard → amount vs *stored* payment → raw payload encrypted at rest.
- **Gapless, locked invoice/credit-note numbering** (`invoicing.py:33-57`); **workshop credit concurrency** (`booking.py:307-340`: `FOR UPDATE` on consume, atomic increment on refund) — the model H-2/H-3/H-6/H-7/M-12 should copy.
- **Enumeration resistance** with a real dummy Argon2 verify on every failure branch; **fail-closed AV** and sanitised object keys at every upload; push-endpoint SSRF validator; Decimal end-to-end with per-line `ROUND_HALF_UP`.
- **Quiz correctness never reaches the learner** (no `is_correct` in any response schema; server-persisted randomisation; time limit against server `started_at`); anonymous surveys carry no `user_id` with a model-visible CHECK; append-only enforcement is two-layer (revoked grant + trigger) for audit/ledger/consent/credit notes/refunds/webhooks; `rule_evaluation` snapshot stored on every completion decision.
- **Test philosophy**: Postgres 18 as the RLS-bound `app_user`, real ClamAV/EICAR, real ffmpeg with the served manifest checked byte-for-byte, real RS256 SSO, real Payfast signature algorithm, `asyncio.gather` races for idempotency/credits/seats/slots; the H1 regression suite is exactly what the audit asked for; feature flags got permission/isolation/audit tests on day one; e2e fixtures use the real API with rate-limit budgeting and a `REQUIRE_API_E2E` hard-fail.
- **Supply chain**: every Action SHA-pinned with a version comment, Trivy/gitleaks from signed sources, `permissions: contents: read`, keyless cosign with identity-bound verification, SBOM attested per digest, digest-pinned non-root images with dev deps and the npm CLI stripped, `.env.prod` `chmod 600`, backup script refuses to run without an off-box remote.
- **CSP** with nonce + `strict-dynamic`, no `unsafe-inline` for scripts, `frame-ancestors 'none'`; no `dangerouslySetInnerHTML` anywhere in `app/`; articles through `react-markdown`; every external href protocol-checked; hex-validated colours; service worker is navigations-only, network-first, never caches data.
- The "why" comments in CI, scripts, `core/` and tests are the best documentation in the repo and are accurate far more often than the prose docs.
